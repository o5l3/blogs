이번 주에는 분석가의 덤프 분석 화면과 분석 엔진을 한 벌로 합쳤고, SQLite summary DB 의 체크포인트 멈춤과 전수 읽기를 없애 조회·이벤트 처리 성능을 끌어올렸다. 매니저 쪽에서는 특정 프로세스를 통계에서 빼는 「관찰 제외」 기능을 매니저·API·DB 전체에 걸쳐 새로 짰고, 프로세스 화면은 실행 목록 추세·비교 중심의 새 판으로 전면 교체했다. 인프라는 nginx 로컬 권한 상승 취약점(nginx2root) 대응으로 mainline 버전으로 전환했고, 노드 그룹별 현황은 개편 직후 나온 결함을 한 회차에 묶어 고쳤다. 사내 진단 도구 두 개는 Orange-Tools 저장소 하나로 모았다.

## kimyh-orange

기존 프로세스 화면의 버전 예측 탭을 빼고 실행 목록 추세·비교 중심의 새 판으로 바꿨다. 조직도가 없는 고객사는 도메인 단위로 묶고 도메인도 없으면 그룹 탭 자체를 숨겨 조직 구조가 없는 환경에서도 화면이 깨지지 않게 했고, 실행 목록 열 이름을 「부하 지수(노드당)」로 바꿔 수치 기준을 분명히 했다. 구버전 크롬(100)에서도 컨테이너 쿼리·subgrid·Switch 대체 구현으로 레이아웃이 깨지지 않도록 호환성을 맞췄다. 매일 버전 목록과 CVE 를 대조해 심각한 취약점이 발견되면 바로 알리는 tech-news 루틴도 새로 짰고, 1.6.242.1118 회차 릴리즈 노트도 같은 주에 게시했다.

## wychoi-orangelabs

흩어져 있던 사내 진단 도구 OrangeTCPSymptomTester 와 OrangeDNSMonitor 를 Orange-Tools 저장소 하나로 모았다. 두 프로젝트를 같은 솔루션에서 빌드하면 중간 산출물 경로가 겹쳐 MSB8028 경고와 함께 간헐적으로 빌드가 깨지던 문제를, 프로젝트별 중간 출력 폴더(IntDir)를 분리해 해소했다. 두 도구의 사용 안내도 같이 다시 써서 바로 쓸 수 있게 정리했다.

## hja-orange

노드 그룹별 현황 개편 뒤 나온 결함을 바로 정리했다. 이슈 중복 제거 키가 맞지 않아 같은 이슈가 여러 번 잡히던 것, 위험 이상 판정에서 차이 항목이 어긋나던 것, 이슈 조회 범위와 일별 날짜가 안 맞던 것, 기종이 다른 노드를 같은 기준으로 비교해 생기던 오탐까지 한 회차에 묶어 고쳤다. 노드 목록을 Excel 로 내보낼 때 빠져 있던 부하 상태 컬럼도 추가해, 화면에서 보는 정보를 내보낸 파일에서도 그대로 확인할 수 있게 했다.

## SungWoo824

모니터링 화면에서 특정 프로세스를 통계에서 빼는 「관찰 제외」 기능을 매니저·API·DB 전체에 걸쳐 새로 짰다. 매니저 프로세스 화면에 관찰 제외 버튼과 관리 창을 두고 제외한 행에는 눈 아이콘을 붙였으며, rest-api 에는 관찰 제외 목록 API 와 감사 로그 분류를 추가해 순위 조회·목록·분류 카운트 전부에서 제외 대상을 걷어내도록 했다. nginx 의 로컬 권한 상승 취약점(nginx2root) 대응으로 패키지가 쓰는 nginx 를 mainline 1.31.9 로 전환하고, update 스크립트가 전환 뒤에도 예전 고정 버전으로 되돌아가던 결함도 고쳤다. 조회 기간이 하루를 꽉 채우는지에 따라 daily·hourly 집계를 자동으로 고르는 bucket=auto 전환에서, 끝 시각 뒤의 값이 다음 구간에 섞여 들어가던 결함도 서버·화면을 같이 고쳤다.

## kim-tigerj

분석가의 덤프 분석 화면과 분석 엔진을 한 벌로 합쳤다. 접힘 상태를 파일에 남기지 않고 화면을 열 때마다 새로 펴지게 바꿔 이전 세션의 접힘이 다음 분석에 영향을 주지 않게 했고, 크래시 요약의 「조치」 줄을 빼고 서명 표시를 「위치」 아래로 옮겨 읽는 순서를 다듬었다. 데이터 위치 주소마다 이름·그 자리를 부른 call·예외 심볼을 바로 옆에 붙여 주소만 보고 원인을 못 찾던 상황을 줄였다.

SQLite summary DB 를 TRUNCATE 하기 전에 잠금 없이 PASSIVE 체크포인트를 먼저 돌리는 전용 연결을 분리해 멈춤을 줄였다. filelist 색인을 CreateTime 과 묶어 경로·이름 최신 행 조회가 전체를 읽고 정렬하지 않게 했고, 커널 이벤트 큐는 워커 4개로 병렬 처리하도록 바꿔 첫 묶음 500행이 summary 연결을 22초 붙잡아 이벤트 처리가 멈추던 현상을 없앴다.

oprobe 를 올려 개체 이름과 스레드 레지스터 표본을 추가로 받고, 분석가가 그 표본으로 깎인 스레드 문맥까지 복구해 읽도록 했다. 32비트 코드 실행 중 잡힌 WOW64 스레드는 원인 모듈을 스택 메모리에서 찾아 비어 있던 「원인 모듈 없음」 표시를 줄였다. 한 은행 고객사의 윈도 10→11 업그레이드 뒤 느려짐 사례를 계기로 윈도 업그레이드 점검과 DNS·인증 이름 풀이도 분석가 수집 항목에 보강했다.

종료 코드가 259(STILL_ACTIVE)로 잘못 읽혀 캐시에 남던 껍데기 프로세스를 걸러내고, 이미 들어간 것도 회수하도록 했다. ofilter 로드 시점에 스레드 0개인 프로세스는 표에 넣지 않게 해 크래시 복제 과정에서 생기는 껍데기를 핸들로 붙잡던 현상을 막았고, 실제로 쓴 파일만 FileClose 메시지로 보내게 바꿔 읽기만 한 PE 파일 때문에 생기는 메시지를 줄였다. SaveFileList 는 수집이 끝난 파일에 더 이상 m_lock2 를 잡지 않게 해 잠금 경합도 줄였다.
