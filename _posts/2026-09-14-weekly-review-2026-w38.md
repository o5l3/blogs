이번 주에는 프로세스 부하 지수의 계산 기준을 다시 세우고, 반복 명령과 결과 보관 정책을 서버와 화면에 연결했다. 자원 baseline의 날짜별 실제값, COM 통신 실패 탐지, 정팀장 DGX v2 이전도 함께 진행했다.

## kimyh-orange

COM 룰의 Value2가 ev.ServerSummary를 사용하도록 여러 룰 파일을 수정해 실제 제공자 정보를 요약에 표시했다.

1.6.242.0910 릴리즈 노트를 게시했고, 전체 노드 부하 요약에서 선택한 프로세스의 상세 화면을 바로 열도록 연결했다.

## wychoi-orangelabs

COM 통신 실패를 수집하는 에이전트 플러그인을 구현하고 실제 실패한 호출만 증상으로 남도록 룰을 나눴다.

ETW 소비가 멈춘 채 남던 결함과 누수를 수정하고 dllhost가 로드한 실제 COM 구성요소를 모듈 정보로 찾게 했다.

## hja-orange

Manager Web의 1.6.242.71 릴리즈 버전을 반영했다.

## SungWoo824

노드 자원 baseline에 LIVE와 DAILY 두 축, 날짜별 실제 관측, 시간대별 가동 정보를 추가하고 매니저 히트맵과 차트를 같은 날짜축으로 맞췄다.

에이전트 업로드 용량 상한을 노드 설정으로 옮기고 Store 문서를 v3로 이전했다. 파일 업로드 완료까지 실제 파일로 시험했다.

기능 권한을 방식별 대상과 그룹별 설정으로 확장하고 조직·그룹·노드 가운데 가장 엄격한 판정을 적용했다.

## smahn9123

반복 실행 규칙 미리보기와 스케줄 관리 API를 만들고 각 회차에 실제 명령을 발행하도록 연결했다.

명령별 결과 보관 기한을 전역 보존 기간과 분리하고 부분 인덱스, 상한 검사, 매니저 설정 화면을 추가했다.

raw sprocess TTL 삭제 부하를 실서버에서 측정해 문서와 migration 주석을 실제 값으로 수정했다. coturn의 서버 내부 접근 경로도 차단했다.

## kim-tigerj

User2 좌표·글꼴·차트·스크롤을 수정하고 시작 프로그램 절과 로그온 지연 표시를 추가했다.

시간당 60을 프로세스 사용량에 따라 나누고 남는 몫을 시스템 공통 영역으로 저장하는 sprocess rev.28을 에이전트·서비스·REST API·매니저에 반영했다.

시작 프로그램의 PID·등록 출처·실행 시간을 저장하고 마지막 로그온 결과를 화면에 전달했다.

정팀장 v2를 DGX vLLM Responses 기반으로 옮기고 제품 사전, 서버 자료 즉답, SYSTEM 권한 점검 명령과 매일 자동 채점을 연결했다.
