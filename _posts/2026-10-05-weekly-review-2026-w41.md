이번 주에는 orange.sys 커널 드라이버에서 파일 열기 중 나던 0x4A 블루스크린과 언로드·콜백 등록 경로를 안정화하고, 핸들 과다 점유·누수를 탐지하는 전담 플러그인을 새로 두었다. 덤프 분석기는 커널 크래시가 어느 시스템 서비스 호출에서 났는지 짚고 심볼 없이 .NET 예외를 사슬째 읽게 됐다. 매니저에서는 스위치 포트별 관측 화면이 올라오고 화면 결함 수십 건을 정리했다.

## kimyh-orange

TCP·DNS 증상을 실패한 곳 단위로 묶고(RULE 97), PC명 중복 룰은 접미사로 원인을 나눠 충돌 이름·상대 IP로 묶게 했다(RULE 91). 룰 번들의 룰 파일 해시를 LF 기준으로 다시 적고(RULE 99), 룰 전반의 키 evidence 표기를 Evidence로 통일했다(RULE 92).

정팀장 시간 요약의 「누가 올렸나」를 CPU 사용률 몫 기준으로 바꾸고 부하 1위 프로그램을 짚게 했다. PC 사용률 변화는 사용 시간 합 대신 시간 평균으로 표기했다. 릴리즈 노트는 패키지 1.6.242.0929 회차를 홈페이지에 게시했다.

## wychoi-orangelabs

TCP 느린 성공(SLOW_SUCCESS) 분석에서 컴파일되지 않던 네트워크 수집 코드와 쓰지 않는 통계 함수를 걷어내고, 임계값을 상수로 두어 보고서에 내보냈다. TCP 장부에서 짝이 맞지 않는 항목을 걸러내고 고아 항목을 빨리 치우게 했다.

## hja-orange

매니저 전반에서 중복 API 호출, 조직도 메뉴 소실, 분류 축 어긋남, 고정 노드 KPI가 삭제를 오프라인에 섞어 세던 것 등 화면 결함 수십 건을 고쳤다. 날짜 입력 2종을 공용 캘린더로 통일하고, 닫힌 패널·접힌 검색창이 스크린 리더에 남던 접근성 문제와 AI 서버 토큰이 화면에 평문으로 보이던 것을 바로잡았다.

전체 노드 부하 요약의 KPI 패널을 복원하고, 상태 갱신을 토스트에서 KPI 칸 목록으로 바꿨다. 앱 전반에서 과한 수치 굵기(font-extrabold)를 걷어냈다. 개발 모드에서만 붙는 GNB 메뉴 「DEV 실험실」을 넣고, 설정 「정보」를 2depth로 바꿔 항목이 하나뿐인 묶음은 좌측에서 바로 링크하게 했다.

## SungWoo824

스위치 포트마다 무엇이 관측됐는지 보여주는 화면을 매니저에 새로 만들고, 에러를 폐기·물리 계층·듀플렉스 갈래로 나눠 근거와 함께 보여줬다. 단말이 올린 증상을 감시 주소 화면에 이어 붙였다.

서버에서는 감시 대상에 단말 증상을 잇는 API 경로와 포트별 기기의 범위 밖 건수를 함께 주는 응답을 만들었다. 자원 baseline 원인 분석의 sprocess 등식 모델을 실측 base 모델로 정정하고, 시스템 몫 on-demand 명령을 @upload_sprocess 계약으로 확정했다.

## smahn9123

하드복원으로 생성 guid가 갈라진 PC가 노드 인덱스와 어긋나던 것을, 구버전 guid로도 같은 노드를 찾도록 고치고 생성 guid 백필 마이그레이션(v0057)을 올렸다. 상위에서 소속이 확실한 PC를 하위 구역 범위로 나눠 두고, 리뷰 큐 필터가 하위 구역까지 포함하게 했다.

패키징에서는 mosquitto가 OpenSSL 3이 아닌 서버에서 사전 빌드 preload가 로드되지 않아 기동에 실패하던 것을, OpenSSL 3이 아니면 preload shim을 설치하지 않도록 바꿔 막았다. 서비스 시작·정지·재시작·상태 스크립트의 목록을 현재 구성에 맞췄다.

## kim-tigerj

C++ 에이전트 UI에 증상 상세 창과 프로세스 정보 창(부하·증상 탭)을 넣고, 대시보드를 닫으면 객체까지 해제해 스크롤 버벅임을 줄였다. 프로세스 「부하」 탭 명령과 진행 중 시간 칸을 더했다.

덤프 분석기에 커널 크래시가 어느 시스템 서비스 호출에서 났는지 짚는 경로 분석과 버그체크 해석(0x4A)을 넣었다. DAC 없이 .NET 예외를 InnerException까지 사슬째 읽고, 크래시 당시 이미지를 WinSxS 하드링크로 역추적해 심볼을 받는다. 결과 JSON 트리를 공용 부품으로 빼 에이전트 UI와 함께 쓰고, 용어 사전 근거를 Microsoft 문서로 달았다.

orange.sys 커널 드라이버에서 파일 열기 중 0x4A BSOD의 원인인 닫히지 않는 클라이언트 포트와 테이블 추가 실패 시 FAST_MUTEX 미해제를 고쳤다. 언로드 중 메시지 스레드가 해제된 필터를 쓰지 않도록 순서를 정리하고, 콜백 등록에 실패하면 감시 없이 로드되던 것을 로드 실패로 보고하게 했다.

핸들을 과하게 쥐거나 누수가 나는 증상을 탐지하는 전담 플러그인과 룰(RULE 98)을 추가했다. RPC 호출이 폭주한 PC에서 에이전트 CPU가 과다하게 쓰이던 것을 COM RPC 수집 선필터로 줄였다. pscore를 rev.31·32로 올려 부하 지수 항목을 담고 업로드 합산을 나눴으며, 하드복원으로 복제된 PC가 재부팅마다 노드를 새로 만들던 문제는 방식별 guid 4개를 함께 보내 구버전 guid로도 같은 노드를 찾게 했다. 정팀장 서버에서는 메모리 총량 오환산과 정리 턴 결론 누락을 포함해 운영 결함 8건을 처리했다.
