## 증상

사내 직원의 PC(Boot Camp로 Windows 11을 올린 MacBook Pro)가 느리다는 제보가 들어왔다. 1:N 명령으로 직접 측정했다.

성능 카운터(Processor Information \_Total)를 1초 간격으로 5회 쟀더니 다섯 번 모두 같은 값이 나왔다.

```
busy 100%, perf 25%, freq 800MHz
Win32_Processor CurrentClockSpeed: 800MHz (정격 3,100MHz)
```

CPU 사용률은 100%였다. 그런데 이것만 보면 "프로그램이 CPU를 많이 써서 바쁘다"와 "속도 자체가 낮아서 늘 바쁘다"를 구분할 수 없다. 전원 설정은 균형 조정, 최대 프로세서 상태는 100%였다. OS 설정 때문이 아니었다.

## 세 가지 원인이 겹쳐 있었다

### 1. 펌웨어 CPU 속도 제한

System 이벤트 로그에 `Microsoft-Windows-Kernel-Processor-Power` ID 37 — "0 그룹에 있는 프로세서의 속도가 시스템 펌웨어에 의해 제한되고 있습니다" — 가 이번 부팅 시각에 8건 남아 있었다. OS가 아니라 펌웨어가 속도를 묶었다는 뜻이다.

### 2. 배터리 이상

전원이 연결돼 "충전 중"인데 남은 양이 0mWh였다. 완충 용량도 비정상적으로 낮았다(이후 배터리 보고서로 확인한 설계 용량 대비 약 29%). 전원이 연결된 채로 한 시간 넘게 잔량이 0에 머무는 것은 정상 배터리에서는 나오지 않는 값이다.

### 3. GPU 드라이버 미설치

`Get-PnpDevice -Class Display` 결과가 "Microsoft Basic Display Adapter"였다. PCI 하드웨어 ID는 분명 AMD 전용 GPU인데 제조사 드라이버가 올라와 있지 않았다. Windows 업데이트 기록을 보니 이 AMD 드라이버는 1월부터 10개월 동안 18번 설치를 시도해 18번 모두 실패했다(오류 코드 0x8024200B 등).

## 셋이 서로 어떻게 묶였는가

이 PC는 13일 동안 절전 상태였다가 배터리가 바닥난 채로 깨어났다. 배터리 잔량이 0인 동안 펌웨어가 과열·전력 보호를 위해 CPU를 800MHz로 묶었고, AC로 충전이 진행되면서 그 제한이 저절로 풀렸다. 다시 측정해 보니 MhzLimit이 2,790MHz까지 올라가 있었다.

```
10:20  배터리 0mWh (충전 중)   → CPU 800MHz, perf 25%
11:16  배터리 12,440mWh       → CPU 3,001MHz, perf 93~118%
```

재부팅이나 전원 설정 변경 없이, 배터리가 차오르는 사이에 속도 제한이 풀렸다는 것이 이 관계를 뒷받침한다. GPU 드라이버 미설치는 별개의 장기 문제였다. 화면 그리기를 CPU가 대신 떠맡으면서 체감 속도를 더 끌어내렸다.

## 왜 '사용률'만 보면 놓치는가

CPU가 바쁜데 지금 속도가 기본 속도보다 뚜렷이 낮고 사용률이 그 바쁨을 설명할 만큼 높지 않다면, 프로그램이 CPU를 많이 써서가 아니라 속도 자체가 낮아서 바쁜 것이다. Windows 성능 카운터로 이 둘을 가를 수 있다.

- `% Processor Utility` — 작업 관리자의 "사용률"
- `% Processor Performance` — 기본 속도 대비 지금 속도
- `% Performance Limit` — 전원 정책·전력 한도·과열·하드웨어 문제로 묶인 성능의 상한

이 PC에서 사용률 상위 프로세스를 모아 봐도 상위권에 특별히 무거운 프로세스는 없었다. 범인은 프로세스가 아니라 속도였다.

## 탐지로 만들기

세 증상을 각각 판정 기준으로 잡았다.

- **CPU 속도 제한**: `CallNtPowerInformation(ProcessorInformation)`의 `MhzLimit < MaxMhz`, 또는 성능 카운터 `% Performance Limit < 100`. 지금 속도가 아니라 상한을 봐야 쉬는 중의 정상적인 다운클럭과 구분된다.
- **배터리 이상**: 전원 연결·충전 중인데 남은 양 0이 두 번 연속 관측되거나, 완충 용량이 설계 용량의 80% 미만이면 이상으로 본다.
- **GPU 드라이버 미설치**: PCI 디스플레이 장치가 Windows 기본 드라이버(`Microsoft Basic Display Adapter`)로 도는지를 장치 열거로 확인한다. 장치 관리자의 오류 코드는 0이라 오류 목록에는 나오지 않는다.

가상 PC의 가상 그래픽 장치는 제조사 드라이버가 원래 없는 것이 정상이라 이 판정에서 뺐다.

## 조치와 검증

Boot Camp로 설치된 Mac은 일반 AMD 드라이버 페이지(Adrenalin)로 안내하면 안 된다. AMD가 Boot Camp에는 일반 드라이버를 쓰지 말라고 안내하기 때문이다. 보드 제조사(Apple)를 함께 보고 AMD Boot Camp 전용 드라이버 페이지로 안내를 분기했다.

안내대로 드라이버를 설치한 뒤 실측했다.

```
설치 전: Microsoft Basic Display Adapter
설치 후: Radeon Pro 560, DriverVersion 30.0.13045.22003
```

드라이버 교체 뒤 CPU 속도 제한 탐지도 더 이상 발생하지 않았다. 사용자 체감으로도 팬 소음이 줄고 화면 반응이 빨라졌다.
